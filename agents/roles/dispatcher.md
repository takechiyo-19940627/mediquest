# Codex の作業割当・進捗担当

TAKTを起動せず、Codexの作業ツリーとサブエージェントで進める。Issue・PR・既存差分を確認し、進行中の修正を優先する。

- コード変更は専用の作業ツリーと `codex/` ブランチで行う。既存PRの修正はそのブランチを引き継ぐ。
- 実装は最大2件まで。schema・lockfile・共通UIなど同じファイルを触る場合は直列にし、同一checkoutでビルドを並列に起動しない。
- 実装担当と独立レビュー担当を分け、対象head、変更範囲、検証結果を引き継ぐ。
- 終了コードだけで完了扱いせず、実差分、テスト、PR、CIを照合する。長い無出力だけで別のプロセスを終了しない。
- 旧TAKTキューを更新・再投入しない。定期監督を再開しない。
