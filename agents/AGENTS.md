# Mediquest 自律開発の監督指示

対象リポジトリは `takechiyo-19940627/mediquest`、実装対象は実用側 `app/`。このファイルは定期実行時の監督者が毎回読む。ルートのAGENTS.md、docs/development-process.md、各rolesも参照する。
ユーザーはIssue作成、TAKT投入・並列実行、調査・改善、レビュー対応、条件を満たすPRのマージを継続実行することを承認している。以前の「手動起動・人のみマージ」という方針は、本指示の条件付き自律運用に更新する。

## 役割

- `roles/planner.md`: 未実装要件・不具合からIssueを洗い出す。
- `roles/dispatcher.md`: 依存と競合を見てTAKTへ投入し、並列実行を監督する。
- `roles/maintainer.md`: 失敗原因を調査し、アプリ・workflow・TAKT実体の該当箇所を改善する。
- `roles/reviewer.md`: PRの独立レビューと到着したレビューへの対応を行う。
- `roles/integrator.md`: 条件を満たすPRをマージし、Issue・依存を更新する。

役割は同じ監督者が順に担当してよい。ただし実装と承認レビューは別の読み取り中心のエージェント/コンテキストで行い、自己申告だけで承認しない。独立した調査・レビューにはサブエージェントを使用してよい。

## 1巡の手順

1. 対象repo・現在ブランチ・未コミット変更を確認。ユーザーの作業ツリーを勝手に切替・上書きしない。GitHubとTAKTの状態を読み、前回の未完了処理を先に復旧する。
2. 実行中TAKTのタスク状態・更新時刻・ログを確認。プロセス終了コードだけで成功としない。実行中バッチのqueueを更新しない。
3. PRのレビュー・CI・未解決スレッドを確認。新しい指摘をfingerprint（PR/コメントID/更新日時/head SHA）で重複処理せず、優先して修正する。
4. 失敗を分類して再現・改善。根拠なく同じ入力を再試行しない。
5. レビュー・CIの条件が揃ったPRを再取得してマージする。先行Issueが閉じたら後続をreadyにする。
6. 合意済み要件の未実装分をIssue化。既存のopen/closed Issue・PR・queueを調べ、同じ作業を重複作成しない。
7. 依存解消済みかつファイル競合のないIssueを最大2件までバッチ投入し、TAKTを1プロセスで起動する。無関係な新機能で仕事を増やさない。
8. 状態と証拠を保存。意味のある進捗・完了・失敗・ユーザー判断が必要な時だけ通知し、変化がなければ静かに終了する。次回の起動で続ける。

## 継続の上限と状態

- 並列タスクは最大2。キューを変更する監督プロセスは一つ。TAKT実行中の追加・再投入を禁止する。
- 1巡で新規Issueは最大2、同じ失敗の再試行は1回まで。同じ原因で累計3回失敗したら、そのタスクだけblockedにして原因と必要な対応を記録。他の独立作業は継続する。
- ローカル状態はGit管理外の `.takt/supervisor/` に保存。Issue番号、task名、PR、head SHA、PIDと開始時刻、失敗fingerprint・回数、レビュー済みコメント、次の処理を記録する。秘密情報は保存しない。
- 別巡の実行中プロセスを重複起動しない。PIDだけで所有者を判断せず、開始時刻・実行コマンド・ログも照合する。死んだロックはqueue状態を確認してから復旧し、自動削除しない。
- PC停止・スリープ、Codex/TAKT未起動、認証切れでは継続できない。無期限常駐を保証せず、次回起動時に状態から復旧する。
- 全て完了・外部待ちなら不要な変更を作らず待つ。判断が必要な箇所だけを伝え、承認済みの通常作業で逐一許可を求めない。
