# 問題演習アプリ 要求定義・技術スタック (v0.1)

作成日: 2026-08-15
ステータス: 技術選定完了・設計着手前

---

## 1. 目的

書籍・Webソースから AI で選択式問題を生成し、演習・記録する自分専用アプリを Rust で自作する。
医療情報技師試験の学習に使いつつ、Rust とマルチプラットフォーム開発の学習題材とする。

プロトタイプとして Claude アーティファクト版(React + Claude API + 永続ストレージ)を作成済み。
本プロジェクトはその移植・発展版であり、アーティファクト版を動く仕様書として参照する。

## 2. 機能要件

### 2.1 ソース登録
- 教科書ページの写真(複数枚)とテキスト貼り付けの両方に対応し、併用できる
- 写真は AI で文字起こしし、貼り付けテキストと結合する
- **抽出結果は保存前に確認・編集できる**(このテキストが以後すべての解説の根拠になるため)

### 2.2 問題生成
- ソース登録時に一括生成してストックする(生成数は選択可: 4 / 8 / 12 問など)
- 4 択の選択式。各問は以下を持つ:
  - 問題文 / 選択肢 / 正解番号 / 解説
  - **ソース本文からの逐語引用(quote)** — 解説の根拠
- 生成はソーステキストのみを根拠とし、ソースから正誤を確認できない問題は作らない

### 2.3 演習
- タップで即判定(単一選択)。正誤・正答番号・根拠引用・解説を表示
- 進捗バーとスコア表示
- 出題順はシャッフル。不備フラグ付きの問題は出題から除外

### 2.4 AI 誤り対策(3 段構え)
1. **引用照合**: quote がソース本文と完全一致するか機械照合し、不一致なら警告表示
2. **再検証**: ソース本文を渡して正解の妥当性を AI に再判定させる(妥当 / 誤りの可能性 / 判定不能)
3. **問題誤りフラグ**: ユーザーの最終判断で不備フラグを付与。以後の出題と正答率集計から除外

### 2.5 記録
- 各解答を「正解 / 不正解 / 問題誤り」の 3 値で永続記録
- 全体・ソース別の正答率を表示(問題誤りは分母から除外)
- 直近の解答履歴を一覧表示

## 3. 非機能要件

- **マルチプラットフォーム**: デスクトップ(開発初期)→ Android/iOS(最終目標)を 1 コードベースで
- **UI**: スマホ前提(max-width 640px 相当、タップ操作)。既存 SBO 学習ページのダークテーマ設計言語を踏襲
- **日本語 UI**、専門用語はそのまま表示
- **API キー管理**: クライアントに埋め込まない。OS キーチェーン(keyring)または環境変数
- **データはローカル保存**(SQLite)。端末間同期は将来課題

## 4. 技術スタック

| 領域 | 採用 | 備考 |
|---|---|---|
| 言語 | Rust | stable |
| UI フレームワーク | **Dioxus 0.7.x** | 安定版。0.8 は alpha のため見送り |
| ツールチェーン | dioxus-cli (`dx`) | `dx serve` / `dx serve --platform android` |
| HTTP クライアント | reqwest | Anthropic API 呼び出し |
| 非同期ランタイム | tokio | Dioxus / reqwest と併用 |
| シリアライズ | serde / serde_json | API・DB・モデル共通 |
| DB | SQLite (rusqlite) | 将来 sqlx へ移行余地あり |
| キー管理 | keyring | OS キーチェーン利用 |
| AI | Anthropic Messages API | 抽出・生成・再検証の 3 用途 |

### 選定理由(比較の要点)
- **Dioxus**: 1 コードベースでデスクトップ+モバイルをネイティブ対応。0.7 系が安定。React 風 RSX で アーティファクト版からの移植が素直
- **Tauri 2**: UI が Web 技術で既存 HTML 資産を流用できるが、「全部 Rust で書く」学習目的から外れるため次点
- **Topcoat**: サーバー+ブラウザ型で構成としては魅力があるが、2026 年 7 月公開の実験段階(0.5)で破壊的変更リスクが高く見送り
- **Leptos**: Web 特化のため、モバイルネイティブ要件に合わず見送り

### バージョン注意
Dioxus は 0.4→0.5→0.6→0.7 で RSX 記法・フック API に破壊的変更があった。
ドキュメント・チュートリアル・AI 生成コードは必ず **0.7 前提か確認**する。
- 公式: https://dioxuslabs.com (Learn はバージョン 0.7 を選択)
- API: https://docs.rs/dioxus
- examples: https://github.com/DioxusLabs/dioxus (ブランチとバージョンの対応に注意)

## 5. アーキテクチャ(ワークスペース構成)

```
quiz-app/
├── crates/
│   ├── core/      # モデル(Source/Question/Record)、引用照合、集計ロジック
│   ├── ai/        # Anthropic API クライアント、抽出/生成/再検証プロンプト
│   └── storage/   # SQLite。sources / questions / records の 3 テーブル
└── app/           # Dioxus UI(薄いガワ)
```

UI 層を将来乗り換えても core/ai/storage が資産として残る構成とする。

## 6. データモデル(初期案)

- **sources**: id, name, text(確定した根拠テキスト), created_at
- **questions**: id, source_id, q, choices(JSON), answer, explanation, quote, flawed(bool)
- **records**: id, source_id, question_id, ts, correct(bool), flawed(bool)

## 7. AI 連携仕様

| 用途 | 入力 | 出力 | 備考 |
|---|---|---|---|
| 抽出 | 画像(base64) | 文字起こしテキスト | 1 枚ずつ呼び出し |
| 生成 | ソーステキスト+既出テーマ | 問題の JSON 配列 | 数問ずつ分割呼び出し。重複回避指示を含む |
| 再検証 | ソーステキスト+問題+現正解 | verdict(correct/wrong/unverifiable)+理由 | JSON 出力 |

共通: JSON 出力はコードフェンス除去+寛容パースで受ける。出力トークン上限を踏まえ 1 回の生成問数を絞る。
