# 実用アプリの UI ガイド

対象は `app/`。採用済みの共通方針をまとめる。技術・配色の基本方針は [app-architecture.md](app-architecture.md) を参照する。

## 共通ルール

- 落ち着いた学習ツールとして、装飾より問題文・解説の読みやすさを優先する。
- Nuxt UI の標準部品を優先し、既存部品を再利用する。独自部品は繰り返し使うものを中心に作る。
- 色・余白・角丸は共通のデザイントークンで管理する。画面ごとの独自値をむやみに増やさない。
- スマホから設計し、PC でも問題文が横に広がりすぎない幅にする。
- 本文サイズ・見出し階層・行間を統一し、補足文字も小さくしすぎない。
- 各画面の主要操作を明確にし、主要ボタンの見た目と配置を揃える。
- 読み込み中・データなし・エラー・保存完了の状態を設計する。該当しない状態は無理に追加しない。
- ティール基調でライト・ダーク両対応とする。初期状態は OS 設定に追従し、手動切替と選択の保存に対応する。
- キーボード操作とフォーカス表示を用意し、正誤などの状態を色だけで伝えない。

## 役割に応じた画面

- 教材登録と AI 問題生成は管理者ページにまとめる。学習用の画面にこれらの操作を混在させない。
- 学習者の画面は管理者が用意した問題での演習・履歴確認を中心にする。
- 教材・問題がないとき、管理者には教材登録への案内を出し、学習者には学習できる問題がまだないことを伝える。学習者を教材登録へ誘導しない。

## 実装時の確認

- UI 変更前に本資料と既存の共通部品を確認する。
- スマホ・PC、ライト・ダークそれぞれで読みやすさと操作性を確認する。
- 正常時だけでなく、その画面で起こる読み込み・空・エラー状態も確認する。
- 最初に演習画面を作って見た目と操作を合意し、以後の画面の基準とする。現時点では基準画面は未作成。

## 未決定

- 具体的なトークン値、本文幅、文字サイズと行間
- 選択中・正解・不正解・未選択の具体的な表現
- 解説と根拠引用の具体的な配置・表示構成

演習・公開・不備報告の操作は採用済みの [UX 方針](ux-guidelines.md) を参照する。旧 [要求定義](requirements.md) と異なる場合は UX 方針を優先する。未決定の詳細は確定仕様として扱わない。
