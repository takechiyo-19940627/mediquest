# 過去問CSVの移送

対象: [Issue #93](https://github.com/takechiyo-19940627/mediquest/issues/93)。現行の過去問登録・確認フローにCSV入出力を追加する。旧教材/AI生成セットは対象外。

## 使い方

1. 「過去問の管理」→「新しい過去問を登録」でCSVテンプレートをダウンロードするか、登録済み過去問の確認画面からCSVをエクスポートする。
2. 別環境の新規登録画面でUTF-8のCSVファイルを選択する。件数・内容を検証し、試験名・年度・科目と問題数を表示する。この時点では入力フォームもDBも変更しない。
3. 「CSVの内容をフォームに反映」で入力中の内容を置き換える。問題・正答を確認し、必要なら編集する。確認チェックは常に解除される。
4. 「問題文・選択肢・正答を確認しました」にチェックして登録する。現行の手入力と同じく、登録後は演習できる。画面を離れると未保存の入力は失われる。

読み込みは新規登録だけで利用できる。既存セットの一括更新、問題ID・公開状態・確認記録・解答履歴の移送は行わない。同じCSVを別の新規登録操作で登録すると別セットになる。通信失敗の再送は既存の受付キーで重複を防ぐ。

## ファイル形式 v1

UTF-8（BOMあり/なし）、カンマ区切り、引用符は二重引用符。書き出しはBOMとCRLFを使用する。引用されたセル内のカンマ・引用符・改行を保持する。1ファイルにつき1試験・年度・科目、1〜100問。CSVは2 MiB以下、復元した登録JSONは既存APIと同じ256 KiB以下とする。

列は次の順序で固定する。

```text
format_version,exam_name,year,subject,source_reference,question_number,body,choice_1_id,choice_1,choice_2_id,choice_2,choice_3_id,choice_3,choice_4_id,choice_4,choice_5_id,choice_5,choice_6_id,choice_6,answer_ids,explanation
```

- `format_version`: `1`。
- `exam_name` / `year` / `subject` / `source_reference`: 各行で同じ値を繰り返す。出典メモは任意。
- `question_number`: 同じファイル内で重複しない問題番号。先頭ゼロなどを維持するには表計算ソフトで文字列列として扱う。
- `body`: 問題文。
- `choice_N_id` / `choice_N`: 選択肢IDと本文。2〜6件を順に記入し、使わない末尾列は空欄にする。IDは英数字・アンダースコア・ハイフンからなる40文字以下の一意な文字列。
- `answer_ids`: 正答の選択肢ID。複数の場合は `a|b` のように `|` で区切る。
- `explanation`: 任意の解説。

必須値・文字数・正答の整合性は既存の過去問登録と同じ基準で検証する。列不一致、書式エラー、メタ情報の不一致、重複問題番号、正答指定ミスなどは行番号と理由を表示し、全件の読み込みを中止する。部分登録はしない。

## 表計算と内容の保全

エクスポート時に数式として解釈され得る文字列と先頭アポストロフィをエスケープする。インポート時にそのエスケープを戻すため、本アプリ間の往復で本文を保持する。具体的には、先頭がアポストロフィ、タブ、CR、LFのセルと、空白・制御文字を除く先頭が `=` / `+` / `-` / `@` のセルにアポストロフィを1文字付ける。読み込み時は、先頭アポストロフィを除いた値もこの条件に合う場合だけ1文字戻す。手作業で先頭アポストロフィを入力する場合も同じ規則で二重にする。表計算ソフトが編集時に行う数値・日付変換などは復元できないため、問題番号・年度などは文字列として扱う。

CSVには正答・解説を含む。書き出しAPIは既存の管理者境界を適用し、学習者向けAPIへは追加しない。ファイル名はサーバー側の数値IDに基づく。停止または不備確定の問題を含むセットは書き出しを拒否し、取り込みでその状態が消えることを防ぐ。CSVは問題コンテンツの移送用であり、DB全体のバックアップには既存のバックアップ機能を使う。

## 実装と検証

共有CSVパーサー/シリアライザーをブラウザとサーバーで使う。読み込みはブラウザ上で検証した後、既存の管理者登録APIへ送信する。サーバーも既存入力検証と明示確認を適用し、単一トランザクションで保存する。DBスキーマ・マイグレーション・公開契約は変更しない。

単体テストでCSVの往復と不正入力、HTTP結合テストで管理者境界・停止/不備・別セット登録、ブラウザでテンプレート取得・エラー時の入力保持・反映・明示確認・登録・エクスポート・再インポートを検証する。全7品質ゲート、最新CI、独立レビューの実行結果はPRに記録する。
