# Mediquest 初回ローカルWeb版 受け入れテスト項目書

作成日: 2026-10-31。対象は本人PC上のNuxtアプリです。ユーザーの結果欄はすべて**未実施**のまま用意しています。自動検証の成功は、あなたによる最終受入判断を代行するものではありません。

## 使い方

まず「準備」と「一連の確認手順」を実施し、下表の結果・実施日・備考を記入してください。不合格なら操作、期待した結果、実際の結果、画面URLをIssueへ記録します。教材本文やAPIキーは貼り付けないでください。故障注入や権限の改変が必要な「自動中心」の項目は、通常操作で無理に再現せず検証証拠を確認してください。

重要度「必須」は初回対象です。利用者による確認結果には「合格 / 不合格 / 保留」を記入できます。実AI生成の品質・課金確認は固定AIを使う自動試験と分けます。

## 準備とローカル起動

Node 24.15.0 / npm 11.12.1を使用し、ターミナルの作業場所をリポジトリの `app/` にします。nodenvなら各npmコマンドを `nodenv exec npm` として実行できます。新規確認専用のディレクトリを作り、表示された実体パスを控えてください。この例は既存DBを変更しません。

```sh
npm ci
acceptance_dir=$(mktemp -d /private/tmp/mediquest-user-acceptance.XXXXXX)
acceptance_dir=$(cd "$acceptance_dir" && pwd -P)
export MEDIQUEST_DB_PATH="$acceptance_dir/mediquest.sqlite"
printf '%s\n' "$acceptance_dir"
npm run db:migrate
npm run db:seed
npm run build
export MEDIQUEST_LOCAL_MODE=true
export NITRO_HOST=127.0.0.1
export NITRO_PORT=3300
export MEDIQUEST_LOCAL_ORIGIN="http://127.0.0.1:$NITRO_PORT"
npm run start
```

[学習ホーム](http://127.0.0.1:3300/)を開きます。3300が使用中なら、そのプロセスを勝手に終了せず、`NITRO_PORT` を別の未使用ポートに変更してから `MEDIQUEST_LOCAL_ORIGIN` を設定し、同じポートのURLを開いてください。復元後の起動にも同じ設定を使用します。CLIは.envを自動で読みません。既存データを使う場合は先にバックアップし、以下の専用確認DBと混同しないでください。

AI生成を手動確認する場合は、自分の利用可能なAnthropicモデルIDを `MEDIQUEST_ANTHROPIC_MODEL`、キーを `ANTHROPIC_API_KEY`、`MEDIQUEST_GENERATION_ENABLED=true` に設定して、上記の自分で起動したアプリを再起動します。実際のAPI呼出と課金が発生します。キーを文書・スクリーンショット・Gitへ保存しないでください。実生成未確認のままならG02等の該当欄は「保留」とし、固定応答での自動成功とは区別します。

初回はloopback限定です。固定ローカル管理者（ID 1）を使用し、ログイン・利用者切替・外部公開はありません。

## 管理画面が403になる場合

管理者用ログイン画面はありません。`npm run dev` だけでは管理モード・DBは用意されません。上記の `MEDIQUEST_LOCAL_MODE=true`、`MEDIQUEST_DB_PATH`、DBのmigrate/seedが必要です。起動時の `MEDIQUEST_LOCAL_ORIGIN` とブラウザのscheme・hostname・portを一致させてください。`localhost` と `127.0.0.1`、3000と3001は同じ扱いになりません。使用中ポートを避けてNuxtが別ポートで起動した場合も403になります。

設定を変えたら、自分が起動したMediquestのターミナルでCtrl+Cを押して再起動します。他のClaude/Codexや別アプリを終了しないでください。既存DBを利用する場合はその絶対パスを選びます。既存learnerをadminへ昇格させる操作は行いません。

## 一連の確認手順（A01）

自動試験はテスト専用ビルドの固定AIを使います。通常起動のアプリには固定AIを提供しないため、以下を手動で最初から通すには上記の実AI設定が必要です。実AIを設定しない場合は生成を伴う項目を「保留」とし、既存の専用テストデータで確認できた範囲だけ記録してください。

1. ホームの「教材管理（管理者用）」→「教材を登録」へ進む。タイトルと、自分が利用してよい短い架空教材を入力して「保存する」。
2. 教材詳細でセット名・問数を入力し「生成する」。状態と更新日時を確認し、成功した受付の「下書きセットを確認」へ進む。生成成功だけでは公開されない。
3. 各候補の問題・選択肢・正答・解説・引用を確認する。必要なら「候補 N の内容を編集」→「内容を保存」。全候補について確認チェック→「候補 N の確認を記録」を終えてから、採用チェック→「採用と順序を保存」。引用不一致の場合は警告も確認する。
4. 公開確認チェック→「公開する」。学習ホームへ戻りセットの「詳細を見る」→「演習を始める」。
5. 必要数を選択→「回答する」。保存後の正誤・解説・引用を確認して「次へ」。途中で「中断してホームへ」→再開し、保存位置が保持されることを確認する。「この問題をスキップ」は最後に戻り、誤答にしない。
6. 最後の回答後に「次へ」→「結果を見る」。件数・正答率・各問を確認し、誤答があるとき「誤答を復習する」。履歴から元の演習も確認する。
7. 問題または結果の「この問題の不備を報告」→「不備の理由」→「報告を送信する」で受付内容を確認する。同じ版に未対応の報告がある場合は、その既存内容が表示される。管理メニューの「不備報告」から対象の詳細を開き、「判断」で「問題なし」または「不備確定」を選ぶ。「判断の理由」を入力して「この判断を確定する」。一覧には未対応だけが残り、判断済みの詳細URLでは結果を確認できる。不備の確定は当該版を出題・集計から除外し、過去の答案自体は削除しない。
8. 管理セット詳細で改訂セット名と確認チェック→「改訂下書きを作成する」。変更した候補を再確認し「改訂を公開する」。旧セットの新規開始は止まり、過去の演習結果は残る。

ライト・ダークそれぞれで、PC（1280px）とスマートフォン幅（390px）の主要画面を確認します。Tabで移動しEnterで操作できること、フォーカスが見えること、長い日本語が横にはみ出さないことも確認してください。

## AIなしの手動登録（M04）

1. 管理者として教材を登録し、教材詳細の「手動で問題を登録する」を押す。AIキーは不要。
2. セット名、問題文、2〜6個の選択肢、正答のチェック、解説、教材からの引用を入力する。必要なら「問題を追加」で最大10問にする。
3. 「下書きを保存して確認へ」→全候補の内容確認→採用と順序保存→公開確認→「公開する」。公開前に学習ホームへ出ないことも確認する。
4. ホームから演習して、指定した正答と解説で採点されることを確認する。
5. 保存通信失敗では入力を保持して同じ受付で再送する。画面を離れる前に保存する。保存済みは「セット管理」から開く。

## バックアップ・復元の確認（O02）

上記の自分で起動したサーバーだけをCtrl+Cで停止します。同じターミナル（`acceptance_dir`・DBパス・ローカル起動設定を保持）で次を実行します。出力先は未使用パスに限られ、既存ファイルへ上書きできません。

```sh
npm run db:backup -- "$acceptance_dir/snapshot.sqlite"
npm run db:restore -- "$acceptance_dir/snapshot.sqlite" "$acceptance_dir/restored.sqlite"
export MEDIQUEST_DB_PATH="$acceptance_dir/restored.sqlite"
npm run start
```

教材、公開セット、履歴、中断位置、保存済み回答が一致するか確認してください。元DBとsnapshotは保持します。旧スキーマDBは旧バージョンのCLIでバックアップ・別パス復元し、コピーに対して新版 `db:migrate` を行います。新版restoreに旧スキーマを直接入力すると拒否されます。実データで故障・上書き拒否試験をしないでください。

## 既知の制約・未検証・初回対象外

- 実AIへの課金を伴う呼出し、採用モデルの実生成品質、医学的な正答性は、この固定応答による自動受入では未検証です。管理者による内容確認と引用照合を経て公開してください。引用の一致は正解の保証ではありません。
- 本人PCの固定利用者（ID 1）向けです。外部認証・利用者切替・外部公開/リモート配備、OCR、ネイティブアプリ、オフライン同期、複数AI事業者は初回対象外です。
- 永続生成worker・自動復旧/再課金、AIによる正解再判定、教材横断の成績集計は対象外です。演習単位の結果・履歴・誤答復習は対象内です。
- 教材本文の編集/削除、履歴削除、停止解除・不備解除・同じセットの再公開は提供しません。公開済み内容の修正は改訂版を作成します。
- 教材入力・候補編集入力・改訂受付は画面を閉じると復元できません。生成受付は同じタブのsessionStorageで回復しますが、タブ終了後や別ブラウザへの引継ぎは保証しません。未確定の回答選択も保存しません。
- 未採用候補の全版停止状態は既存DTOに含まれず、その画面で操作した直後の表示だけ保持します。再読込後の停止表示は復元せず、採用・公開の可否はAPIが検証します。
- 依存監査の残存項目は [監査記録](dependency-audit.md) を参照してください。ユーザーの実DBの移行・復元は実施していません。使い捨てDBの成功と区別します。
- TAKT・定期実行は再開していません。他のClaude/Codexプロセスを無断で終了しません。
