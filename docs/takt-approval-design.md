# TAKT の明示承認経路（未接続の設計・試作）

Issue #10 の調査成果。**実行可能な承認経路はまだ導入していない。Issue #5 の再開条件を満たさず、Issue #10 の完了でもない。**

## 確認した接続点

ローカル TAKT 0.49.0 の `dist/infra/claude/options-builder.js` では `onPermissionRequest` があると SDK の `canUseTool` コールバックを作る。コールバックには toolName / input / suggestions / blockedPath / decisionReason を渡す。現状この変換は SDK のキャンセル情報を引き継いでいないため、実接続前に SDK の型とキャンセル伝播を確認し、版固定した変更と回帰テストが必要。

承認要求は実行直前の SDK コールバックから、信頼された監督プロセス経由で人の UI に送る。UI はタスク、作業ディレクトリ、ツール名、入力全文、期限、要求 ID を表示する。人の明示選択を、同じ要求を保持しているコールバックへ一度だけ返す。省略表示だけで承認させない。機密入力は共有ログへ保存しない。

`allow` はその一回の要求のみ。設定の変更、永続的な許可の追加、拒否されたコマンドの別ツールによる実行、権限チェックの無効化を行わない。既存の明示拒否をこの経路で覆してはならない。SDK やホストの拒否が最終的なものであれば停止する。

## オフライン試作

`scripts/takt-approval.mjs` は実コマンド・SDK・ファイル・ネットワークを使わないインメモリの状態機械。呼び出しごとに UUID、task、絶対 cwd、toolName、入力全体、期限を保持する。呼び出し側が別途注入する `trustedDecision` が完全一致する要求と明示的な `choice: allow` を返した場合だけ、保持していた元入力を返す。

状態遷移は pending → allow / deny の一回限り。無回答の期限切れ、キャンセル、明示拒否、例外、不完全応答、入力改変、他要求へのリプレイは deny。期限切れ後の応答は破棄する。承認前後に実行入力を差し替えない。再起動で承認を復元しない。

テストは要求の拘束、改変・再利用、期限切れ、キャンセル、入力コピー、拒否と例外を検証する。実行経路や本人認証の試験ではない。

```sh
node --test scripts/takt-approval.test.mjs
```

## 信頼境界と未解決事項

`trustedDecision` という名前自体には本人認証能力がない。この試作は呼び出し元とコールバックが信頼されていることを前提とし、OS の隔離やユーザー認証を実装しない。ワーカーが同じプロセスで任意コードを実行できるならこの前提は成立しない。

特に、ワーカーと同じ OS ユーザーで動く監督者は、単に別プロセス・別ファイルにするだけでは強い隔離にならない。ワーカーが書ける JSON inbox、同じユーザーの秘密ファイル、PID、UUID、ハッシュ、ファイル権限だけをユーザーの承認証明にしてはいけない。ワーカーが承認を書き込める構成は不可。シェルや任意コードからユーザー UI の入力・認証済みチャネルを偽造できない実際の信頼境界が必要。

実接続までの必須条件:

- ホストが提供するユーザー承認 API、またはワーカーから隔離された認証済み UI/監督サービスの選定と検証。現時点では未選定。
- 同一 OS ユーザーの攻撃範囲を含む脅威モデル、サービス所有者、通信の認証、ワーカーからの UI 操作禁止の保証。
- callback に task/cwd と SDK のキャンセルを実行コンテキストから渡す版固定の修正。ワーカーの自己申告だけでコンテキストを決めない。
- UI 切断、無回答、拒否、同時要求、再起動、期限切れ、入力交換で実コマンドが実行されない統合試験。
- 表示した cwd のシンボリックリンクや作業ツリー内容が承認後に変わる問題、承認したスクリプトが後から変わる問題への対策。文字列一致だけで実行対象の同一性を保証しない。
- 独立レビュー後、人が明示承認する無害な操作一件の試行。これらを満たすまで workflow/queue へ接続しない。

本試作の成功を「コマンド承認が利用可能」「安全な自律実行が完成」と報告しない。
