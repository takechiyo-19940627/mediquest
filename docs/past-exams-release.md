# 過去問を中心にした初回リリース

対象Issue: [#91](https://github.com/takechiyo-19940627/mediquest/issues/91)。ユーザー指示により、過去問の手入力・貼り付けを優先する。TAKTと定期実行は停止を維持する。

## 操作

ホーム →「過去問を登録する」→ 試験名・年度・科目、問題番号・本文・選択肢・正答を入力 → 内容確認 → 登録 →「この過去問を解く」。解説・出典メモは任意。1〜100問、各2〜6選択肢、複数正答に対応する。1問から登録し、確認・修正画面で後から問題や解説を追加できる。

教材の作成、AI設定、採用・公開の別操作は不要。旧教材・問題セット管理URLは過去問管理へ案内する。過去問以外のデータはホームの新一覧に出さないが、既存履歴を削除しない。

## 保存と修正

新規登録は過去問メタデータ・問題版・演習対象・受付記録を同じトランザクションで保存する。修正は新しい版を作り、以前の版をアーカイブする。中断中の演習と以前の回答は当時の版を参照する。改訂により旧版になった過去問の誤答復習は、公開中の後継版が存在する場合に限り当時の問題で作成できる。

問題番号の変更でも元の問題の同一性を保持する。停止・不備確定の状態は通常の編集で解除しない。編集画面にその状態を表示する。新たなAPI呼出でも元の問題版が編集対象の過去問に所属することを確認する。

応答を受信できないときは同じ受付で再確認する。競合時は入力をコピー・ファイル保存してから最新の過去問を開ける。入力画面を離れる前に保存が必要なことを表示する。

## 移行とテストの変更理由

DB移行は過去問・問題番号・受付用の3テーブル追加。既存の教材・問題・演習・回答を削除しない。旧オリジナル登録・生成APIは互換性維持のため残し、過去問の変更には使えないようにする。

旧UIの教材生成・候補採用・引用確認・下書き公開操作は今回のスコープから外れたため、対応するブラウザ試験を過去問登録・修正へ置き換える。必須ゲートのskipや期待値の緩和は行わない。旧APIのunit/integration試験、既存の演習・履歴・不備報告ブラウザ試験は保持し、既存データの互換性を検証する。

新しい統合ブラウザ試験は、AI無設定の本番ビルドで登録・演習・誤答復習・改訂後の履歴保持を検証する。競合時入力救済、応答消失時の再送、403での私的内容消去、公開カタログのページ送りと正解非公開、バックアップ復元後の再開を確認する。ライト/ダーク・PC/スマホのスクリーンショットとaxe検査を保存する。

本人確認用は [受け入れテスト項目書](acceptance-test-checklist.md)。自動検証結果と本人の受け入れ判断は分けて記録する。
