# 実用アプリの実装方針

- 演習・問題公開・不備報告は `../docs/ux-guidelines.md` の採用済み方針に従う。旧要求定義と異なる場合は UX 方針を優先する。
- 技術構成は `../docs/app-architecture.md` を参照する。
- UI の変更前に `../docs/ui-guidelines.md` を読み、既存の共通部品とデザイントークンを確認する。
- Nuxt UI の標準部品と既存部品を優先し、画面ごとに独自のスタイルや操作規則を増やさない。
- スマホ・PC、ライト・ダーク、キーボード操作、および該当する読み込み・空・エラー状態を確認する。未確認の内容は報告する。
- 合意された演習画面ができたら他画面の基準とする。未決定事項を確定仕様として扱わず、提案と実装済みを区別する。

- 開発は `../docs/development-process.md` の Issue → 計画 → 実装 → 検証 → レビュー → PR の流れに従う。受け入れ条件を期待値の根拠にする。
- テスト削除・skip・品質設定の弱体化で合格にしない。検証結果と未確認事項を区別し、未構築のゲートを成功扱いしない。
